# Веб-интерфейс Requirements Validator 2.0.1

В архиве находится локальный русскоязычный прототип. В демонстрации используются исходный банковский PDF, сохранённый индекс строк, исходный журнал и отчёты Markdown и JSON. Новый анализ запускается из браузера через тот же CLI и Python-ядро. Автономный HTML включает отчёт и доступный индекс исходника.

**Выполнена только статическая проверка.** Приложение, Docker Compose, сборка, браузер, тесты и обращения к провайдерам не запускались. Реальный запуск подтвердит жизненный цикл контейнера и процессов, загрузку и отмену, переключение панелей и фокус, доставку SSE и восстановление соединения, поведение скачиваний и работу HTML из `file://`.

## Запуск на компьютере владельца

Распакуйте архив и выполните команду из каталога с `compose.yaml`. Для первого запуска используйте актуальный Docker с Compose v2.

```sh
docker compose up --build
```

Откройте `http://localhost:8000`. Compose публикует порт на `127.0.0.1`. После первоначальной сборки демо работает с локальными файлами. Остановка контейнера выполняется командой `docker compose down`.

Для анализа с OpenAI скопируйте `.env.example` в `.env` и заполните `OPENAI_API_KEY`. В Windows PowerShell для копирования используйте `Copy-Item .env.example .env`, в POSIX-совместимой оболочке — `cp .env.example .env`. Затем заново выполните `docker compose up --build`. Настройки альтернативного совместимого провайдера и модели описаны в `docs/CONFIGURATION.md`. Ключ остаётся в окружении серверного процесса. Перед отправкой браузер сообщает о передаче текста провайдеру и возможном списании средств.

Для обычного образа CLI остаётся прежняя команда `docker build -t bcc-reqvalidator:2.0.1 .`. Пример вызова контейнера CLI приведён в `README.md`.

## Исследование и дизайн

В Zotero переход из аннотации открывает страницу первоисточника, а сама аннотация остаётся доступной как цитата. В Adobe Acrobat комментарий связан с выделением в тексте, а замечания можно просматривать в отдельной панели. Для валидатора эти паттерны объединены в действие из карточки замечания к точному диапазону исходника, с отдельным действием для каждой цитаты. При отсутствии привязки карточка сохраняет дословную цитату и объясняет, почему переход недоступен. [1, 2]

На широком экране текст ТЗ и список замечаний занимают примерно 55 и 45 процентов рабочей области и прокручиваются отдельно. Фокус остаётся на выбранной карточке или кнопке цитаты. На узком экране переход показывает документ и переносит фокус к подсвеченной строке. Переключатель «Замечания» возвращает его к карточке или к кнопке цитаты. Нативные кнопки и поля, видимый фокус, подписи уровней и режим уменьшенного движения применены с учётом рекомендаций W3C и браузерного стандарта. [3–5]

В спецификации предложены React и TypeScript. Для трёх состояний рабочего пространства и общей версии просмотрщика выбран JavaScript с нативным DOM. Просмотрщик подключается как обычный скрипт в приложении и встраивается в скачиваемый файл вместе с CSS. Это позволяет работать из `file://` без импорта модулей, отдельного JavaScript-сборщика и сетевых ресурсов. Данные документа и отчёта выводятся как текст. JSON встраивается в блок данных со спецсимволами, экранированными до разбора HTML. [6–8]

Тонкий сервер на стандартной библиотеке Python использует существующие извлечение, настройки и CLI. Docker сохраняет общий слой с прежними зависимостями и добавляет цель `web`. Для прогресса выбран `EventSource`. Передача идёт с сервера в браузер, команды запуска и отмены остаются отдельными HTTP-запросами. События несут снимок состояния, поэтому после разрыва браузер может получить актуальный снимок без получения каждого промежуточного сообщения. [9–14]

## Интеграция

```text
Браузер → локальный сервер → отдельный процесс web.worker → reqvalidator.cli.main
       ← снимок SSE / HTTP ← структурированные события RunTimings
       ← отчёт и SourceLine ← review.json, review.md и индекс сохранённого исходника

Браузер → демо → reports/submission.* + web-demo/*
Просмотрщик → HTML с встроенными JS, CSS и данными → file://
```

Python читает документы и считает SHA-256, запускает движок, сохраняет отчёты, управляет рабочими каталогами и отправляет состояние. Браузер отображает события, ищет и фильтрует замечания, проверяет адреса цитат и формирует автономный HTML. Для веб-процесса предусмотрены отдельные наблюдатели CLI. Консольный интерфейс, формат stdout и stderr, коды возврата и схема JSON сохранены. Дополнительные роли QA и API и внешняя сверка доступны через существующий серверный профиль. `rewrite` остаётся в CLI.

Привязка проверяет равенство SHA-256, присутствие строк и соответствие страниц. Номера строк и столбцов начинаются с единицы. Конечный столбец включён. Столбцы считаются в Unicode-кодовых точках, как в Python. Между строками используется `\n`. Извлечённый по координатам текст должен дословно совпадать с цитатой. Это правило действует в браузере и в автономном HTML.

В журнале живого прогона отдельно отображаются фоновый запрос проверки всего документа и ожидание его результата. Оценка остатка относится к локальным пакетам. Счётчики вызовов, замеры и замечания доступны из записанного JSON. При наличии отчёта после ошибки его можно открыть с отметкой о частичном покрытии. Сервер выполняет один анализ одновременно и хранит не более 24 записей прогонов. Журнал живого прогона содержит до 180 последних событий. Исходный файл удаляется после выхода процесса. Записанные результаты хранятся около часа, а временное хранилище очищается при остановке контейнера.

## Статически сверенные маршруты

| Действие | Связь с данными | Что проверено чтением кода |
| --- | --- | --- |
| Открыть пример | `/api/demo/report`, сохранённый `submission.json` и индекс `web-demo/source-lines.json` | Конфигурация провайдера не нужна. Индекс относится к точному PDF. |
| Добавить PDF к демо без исходника | `POST /api/demo/source`, тот же загрузчик `SourceLine` | Управление появляется при отсутствии исходника. Извлечение выполняется локально. Чужой PDF не даёт перейти к цитате, если SHA-256 отличается. |
| Воспроизвести прогон | `/api/demo/replay`, `web-demo/progress.log`, `report.reviewed_at` | Интервалы берутся из относительных отметок лога. Дата отображается по паспорту с исходным часовым поясом. Просмотр отчёта доступен сразу из экрана записи. |
| Поиск, фильтры, сброс и цитаты | Поля `findings`, `severity`, `criterion`, `evidence` и `SourceLine` | У карточек есть объяснение, исправление, сценарий при наличии и отдельные цитаты. Несовпадения дают текстовую диагностику. |
| Импорт JSON | Выбранный локальный файл и общий просмотрщик | Для отчёта без исходника сохраняются цитаты, фильтры и экспорт. |
| Скачать Markdown, JSON или HTML | `/api/demo/download/{md,json}`, `/api/runs/{id}/download/{md,json}` и экспорт просмотрщика | MD и JSON из готовых прогонов берутся из сохранённых файлов. HTML использует тот же рендерер и проверку привязок. |
| Загрузить и запустить | `POST /api/runs`, проверка файла и согласия, отдельный процесс CLI | PDF, DOCX, MD и TXT. Лимит 20 МиБ. Выбранная параллельность от 1 до 8 передаётся в `--concurrency`. |
| Прогресс и повторное соединение | `/api/runs/{id}`, `/api/runs/{id}/events` | Ход прогона приходит снимками. После обрыва связи и обновления страницы доступен актуальный снимок сохранённого прогона. |
| Отменить или открыть результат | `POST /api/runs/{id}/cancel` и `/api/runs/{id}/report` | Отдельные состояния ожидания, работы, завершения, ошибки и отмены. Доступ к отчёту зависит от наличия записанного JSON. |

Содержимое входных архивов сверено по SHA-256 для двух отчётов сдачи, исходного модуля извлечения, эталона и оценщика. SHA-256 демонстрационного PDF совпал с индексом и паспортом. Для 58 замечаний сверены все 195 цитат по страницам, строкам и столбцам. Индекс содержит 197 строк на четырёх страницах. В исходном журнале 44 строки с неубывающими отметками от 0 до 352,4 с. Дата из паспорта — `2026-11-27T01:43:54+05:00`. Входные отчёты и материалы оценки сохранены.

Новых пакетов и отдельного lockfile нет. Веб-цель использует существующий `requirements.txt` с закреплёнными версиями. Прототип предназначен для локального использования. Многостраничные PDF без текста требуют OCR до загрузки. Веб показывает индекс извлечённого текста, включая страницы и номера строк. Стартовые часы прогона нельзя восстановить из журнала с относительным временем.

## Проверки после запуска

**Без ключа**

1. На первом экране запуск нового анализа заблокирован с объяснением. Откройте пример, нажмите на замечание, затем на другую цитату этой карточки. Сверьте выделение, номер строки и страницу.
2. Проверьте поиск, совмещение фильтров, сброс и пустую выборку. Пройдите эти действия клавишами `Tab`, `Enter` и `Space`. Сузьте окно и проверьте переход из замечаний в документ с сохранением фильтра.
3. Воспроизведите журнал и сравните начало, несколько строк и конец с `web-demo/progress.log`. Откройте отчёт до окончания записи и после него. Проверьте подпись о времени из паспорта.
4. Скачайте MD и JSON, затем откройте скачанный JSON с первого экрана. Убедитесь, что цитаты видны даже без исходника. Скачайте HTML из демо и из JSON. Отключите сеть, остановите Compose и откройте оба файла напрямую. Проверьте фильтры, переходы и предупреждение об отсутствующем исходнике.
5. Откройте `tests/web-report-smoke.html` из распакованного каталога. Синтетическая фикстура проверяет Unicode, диапазон из нескольких строк, пустую промежуточную строку, несовпадения и текстовый вывод разметки.
6. При работающем Compose запустите `py -3.15 -m unittest tests.web_http_smoke` на Windows или `python3.15 -m unittest tests.web_http_smoke` на Linux и macOS. Проверки обращаются только к локальному серверу без ключа.

**С рабочим ключом**

1. Загрузите короткий MD или TXT, подтвердите отправку, выберите параллельность и дождитесь результата. Повторите с PDF с текстовым слоем и DOCX. Сверьте текст, паспорт, вердикты и скачивания.
2. Во время анализа обновите вкладку и проверьте восстановление. Временно оборвите соединение, затем проверьте получение снимка. Отмените другой прогон во время работы и запустите новый.
3. Проверьте ввод без текста, неверное расширение и превышение лимита. Для сбоя провайдера проверьте безопасное сообщение. Для случая с записанным частичным отчётом проверьте предупреждение о покрытии и скачивание. После срока хранения проверьте ответ на запрос истёкшего прогона.
4. Сравните `--progress --timings` у обычного CLI до и после изменений. Для исполнения существующих автоматических проверок без провайдера используйте команды из `docs/MODES.md`.
